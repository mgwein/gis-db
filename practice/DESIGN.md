## 1. Purpose and reader map

This record is the single source of truth for the gis-db practice build. It merges four architect proposals (delivery, grader, ai-operator, geo) and the binding decisions of the handoff into one design. Several agents work from it **in parallel and without talking to each other**:
- the mock-brief writer;
- the data-spec writer;
- three playbook writers;
- the data-generator author;
- the critics;
- later, the Step B executors and verifiers.

Every name, number, path and format they need is fixed here. Where a value must come from running the generator, this record gives the prototype value. The generator's `practice/answer_key.json` is authoritative, and Step A.4 reconciles the documents with it.

**How this record was checked.** The decide agent probed the following on the environment's versions: uv 0.11.16, FastAPI 0.143.0, Starlette 1.7.0, SQLAlchemy 2.1.4, Alembic 1.20.0, Pydantic 2.14.0, structlog 26.1.0, uvicorn 0.54.0, pytest 9.1.1 and ruff 0.16.10.
- **uv:** `uv init` flags.
- **Alembic:** the `render_item` hook, plus `alembic check` and `compare_metadata == []` on Postgres and SQLite.
- **Database behaviour:** the UTC type, the accounting CHECK and FK enforcement on both dialects.
- **Logging:** the structlog recipe with `caplog` tests and all-JSON uvicorn output.
- **Pydantic:** timestamp parsing and error types.
- **Practice data:** the data-set geometry, via a modified copy of the geo prototype. It reproduced every geo value and gave the new values in §7.

The geo formulas and the test table in §6.g come verbatim from the geo proposal, which verified them (26 tests green).

Two audits followed (consistency and technical), and their fixes were probed the same way (Step A.1 revision, 2026-10-08):
- the ruff config that excludes `practice/` and `*.md`;
- the revised `gate` function;
- formatting the autogenerated migration;
- the Step B clone flow;
- the optional Pydantic fields and the reason mapping;
- the `ZoneSummary` validator;
- the brute-force fragilities fixed in §7.7.

**Words used in this record:**
- *trajectory*: a time-ordered sequence of positions (a flight, in practice).
- *zone*: a circle on the sphere.
- *pass*: one visit of a trajectory's path to a zone, with an entry and an exit.
- *intersection*: a point where two trajectories' paths meet, of kind crossing, overlap_start or overlap_end.

"Small" and "large" are CoderPad's two models.

## 3. Placeholder registry and PLAN.md

### 3.1 Placeholders

**Syntax:** `<NAME=value>`. NAME is upper snake case. The value is the practice value, written in full at **every** occurrence. A value never contains `<` or `>` (arrows are written `→`), so the pattern `<([A-Z][A-Z0-9_]*)=([^>]*)>` recovers it whole, by hand or by a Step B fill.

- PLAN §3 ends with a "Placeholder values" table (`NAME | value`) holding every name below except `BRIEF`, with the values for this brief. P0.2 writes it, and Verify 0's review checks it against the profile.
- PLAN §1 Conventions tells the model: "Tokens written `<NAME=value>` in a prompt mean: use value. If PLAN.md §3 "Placeholder values" gives NAME a different value, use PLAN's value and say so in your reply." A value the candidate forgets to overwrite is therefore harmless.
- On the day, the candidate still overwrites the values of each prompt before sending it, and makes the day-of edits that placeholders cannot carry (Appendix E.1: P3.1's format cases, mandated paths and units, an extra analysis). Rule: never send a prompt before its day-of edits are done.
- Placeholders appear only inside prompt (```text) blocks.
- Playbook writers use no other placeholder names. Anything else brief-specific is cited as "per PLAN §n".

### 5.2 Escalation

- **Small fails once:** send the phase's "If it fails" prompt to the same chat with the failure tail (≤ 20 lines).
- **Small fails a second time, or fails once after minute 120:** re-send the original prompt to the large model in a fresh chat, with the failure tail.
- **Large fails twice:** fix it by hand or apply the cut list.
- **Any fix of ≤ 5 lines:** make it by hand with no AI, and note "hand fix" in AI_LOG.md.
- **Geometry and unit conversions:** never retried on the small model.
- **Exception:** P5.1 escalates to the large model on its first failure (§5.1).

### 5.3 Token rules

- A fresh chat per phase, opened with the kickoff header (§5.4), pasted in one message with the chat's first prompt.
- Only `DATA_PROFILE.md` reaches the models, never the raw data files (PLAN §3 lists them).
- Paste only the failing tail (≤ 20 lines). Ask for terse replies.
- **Expected spend:** an agent re-sends its context on every tool call, so a prompt costs about context × tool calls: small 50–150k, large 150–400k. 8 small and 9 large prompts give about 1.8–4.8M, plus 50% for retries about 3–7M, inside 10–20M.
- **Tripwire:** a prompt that runs past about twice its normal range has stopped converging: about 15 tool calls (or 300k tokens) on the small model, about 20 tool calls (or 600k tokens) on the large one. Stop it and narrow it (recovery R6).

```bash
gate() {   # "gate lint" skips pytest: used after P2.1 and P6.3, before the human step creates the migration
  git status --short && git diff --stat
  local rc=0 hits
  hits=$(grep -rnE "session\.query\(|declarative_base|orm_mode|class Config:|@validator|@root_validator|parse_obj|from pydantic import BaseSettings|AsyncSession|create_async_engine|asyncpg|aiosqlite|func\.now\(\)|text\('now\(\)'\)|on_event\(|postgresql://|psycopg2|utcnow" src tests migrations scripts 2>/dev/null)
  if [ -n "$hits" ]; then printf '%s\n' "$hits"; echo "FORBIDDEN API FOUND"; rc=1; else echo "conventions grep clean"; fi
  hits=$(grep -rnE '<[A-Z][A-Z_]+=' src tests migrations scripts 2>/dev/null)
  if [ -n "$hits" ]; then printf '%s\n' "$hits"; echo "PLACEHOLDER LEFT"; rc=1; fi
  uv run ruff format -q . && uv run ruff check --fix -q . || return 1
  [ "${1:-}" = lint ] && return "$rc"
  timeout 120 uv run pytest -q -x 2>&1 | tail -n 15
  [ "${PIPESTATUS[0]}" -eq 0 ] || rc=1
  return "$rc"
}
```

The grep results are captured, not tested by exit status. GNU grep exits 2 when a listed directory is missing (`migrations/` until Human step 2.a), even after printing a match, and `&& … || echo clean` would then report "clean" over a forbidden API. The function returns non-zero on a forbidden API, a leftover `<NAME=` token, a ruff failure or a pytest failure (pytest's own status, read from `PIPESTATUS`), so `gate && …` never commits red. Verified with bash and a stubbed `uv`: clean 0, lint mode 0, pytest failing 1, ruff failing 1, forbidden API 1 (also in lint mode), leftover token 1, and no match on ordinary comparisons such as `a < b`.

**`src/gisdb/db.py`** (verified on both dialects):
- `make_engine(url) -> Engine`:

**UTC everywhere:**
- Every timestamp column uses `UTCDateTime` (§6.c). It raises on naive values at bind time, attaches UTC to naive values read back from SQLite, and converts aware values to UTC.
- Pydantic serializes UTC datetimes with a trailing `Z`, for example `"2024-05-01T09:35:55Z"`.
- Python code gets the current time with `datetime.now(UTC)`. `datetime.UTC` exists from 3.11 on; never use `utcnow`.

### 6.d Ingestion

**CLI:**
- `uv run gisdb ingest [PATH ...]`, with default `data`.
  - A directory expands to its `*.json` files sorted by name (not recursive); files are taken as given. A PLAN §5 DELTA may set another file order (Appendix E.8: referenced entities first); the practice order is by name.
  - Stdout gets exactly one JSON line, keys in this order: `{"ingest_run_id", "status", "seen", "inserted", "updated", "unchanged", "duplicates", "rejected"}`.
  - Exit 0 if `status == "succeeded"`, else 1. Logs go to stderr.
- `uv run gisdb stats` prints `json.dumps({table.name: row_count for table in Base.metadata.sorted_tables}, sort_keys=True)`.

When PLAN §3 types the key as an integer (DATA_PROFILE.md: `int`), that model's ConfigDict adds `coerce_numbers_to_str=True`; without it an integer key fails with `string_type`, which maps to `invalid_value` (verified on Pydantic 2.14).

- The shapes below are the practice ones (P3.1's "Shapes" sentence); on the day they follow PLAN §3:

  - `AircraftIn(icao_type: str | None = None)`;
  - `FlightIn(flight_id: str (1-64 chars), callsign: str | None = None, aircraft: AircraftIn | None = None, origin: str | None = None, destination: str | None = None, positions: list[PositionIn])`;

**Normalization, in this order. The first failure rejects the whole record.**
1. **Pydantic validate.** On `ValidationError`, the code is `reason_from_validation_error` of the first error:
   - `missing`, or any error whose `input` is `None` (a null required field, e.g. `flight_id: null` gives `string_type`) → `missing_field`;
   - a type starting with `datetime` or `timezone` → `invalid_timestamp`;
   - `greater_than`, `greater_than_equal`, `less_than`, `less_than_equal` → `out_of_range`;
   - anything else → `invalid_value`.

   Timestamps follow `TIME_FORMATS`. When every form carries a UTC offset or is an epoch number (practice), the field is `AwareDatetime`: it accepts ISO-8601 with `Z` or an offset and integer epoch seconds (and reads numbers above 2e10 as epoch milliseconds), and it rejects naive strings (`timezone_aware`) and impossible times (`datetime_from_date_parsing`). When PLAN §3 says naive times are UTC, the field is `datetime`, and step 2 attaches UTC to naive values (`value.replace(tzinfo=UTC)`). All of these behaviours were verified on Pydantic 2.14.

   The rules are checked in the order listed. Verified on Pydantic 2.14:
   - a null `flight_id`, `positions`, `ts` or `coord` gives `missing_field`;
   - an empty `flight_id` gives `invalid_value` (`string_too_short`);
   - absent `callsign`, `aircraft`, `origin` and `destination` are accepted as None.
2. **Positions.**
   - `ts = ts.astimezone(UTC)`. Pydantic keeps `+02:00`, so this conversion is required.
   - Unpack the coordinates per `COORD_ORDER` (practice: `lon, lat = coord`, because it is `[lon, lat]`; named fields are read by name).
   - Outside −90 ≤ lat ≤ 90 or −180 ≤ lon ≤ 180 → `out_of_range`. Then `lon = ((lon + 180) % 360) - 180`, so 180 → −180.
   - Altitude per `ALT_UNIT` (practice: `alt_m = alt_ft * 0.3048`; None stays None).
3. **Order and duplicates.** Sort by `ts` and drop exact duplicate points (same ts, lat, lon, alt_m). Two points left with the same `ts` → `conflicting_points`. Fewer than 2 points → `too_few_points`. Then `seq = 0..n-1`, `started_at`/`ended_at` = first/last `ts`, `point_count = n`.
4. **Zones.**
   - The centre per `COORD_ORDER` (practice: `lon, lat = coordinates`) with the same range rule.
   - Radius per `RADIUS_UNITS`: with a unit field, the unit compared case-insensitively (practice: `"nm"` → × 1.852, `"km"` → × 1.0, anything else → `invalid_value`); with a fixed unit and no unit field, its factor (for example metres × 0.001).
   - `radius_km` must satisfy 0 < r < 10000, else `out_of_range`.
5. **Content hash.** `sha256(json.dumps(payload, sort_keys=True, separators=(",", ":"), default=lambda v: v.isoformat()))` hex.
   - Trajectory payload: `{trajectory_id, <the TRAJECTORY_ATTRS columns>, points: [[ts, lat, lon, alt_m, <the POINT_ATTRS values>], ...]}`, after steps 2–3; practice: `{trajectory_id, callsign, aircraft_type, origin, destination, points: [[ts, lat, lon, alt_m], ...]}`.
   - Zone payload: `{zone_id, <the ZONE_ATTRS columns>, center_lat, center_lon, radius_km}`; practice: `{zone_id, name, center_lat, center_lon, radius_km}`.
   - Because the hash covers the normalized record, epoch vs ISO and offset vs `Z` give the same hash, and unknown fields are ignored.

**Reason codes.** These are the exact strings, also enforced by `ck_ingest_rejections_reason_code_valid`:

| Code | When |
|---|---|
| `invalid_file` | File not JSON or unrecognized top-level shape |
| `missing_field` | Required field absent or null (including the natural key) |
| `invalid_value` | Wrong type, unparseable number, unknown radius unit, non-Point geometry |
| `out_of_range` | Latitude/longitude out of range; radius not in (0, 10000) km |
| `invalid_timestamp` | Timestamp unparseable or without a UTC offset |
| `too_few_points` | Fewer than 2 distinct positions |
| `conflicting_points` | Same timestamp, different position in one record |
| `duplicate_key_conflict` | Key already seen earlier in this run with different content (the first copy wins) |

A brief with cross-file references (a track whose vessel is not in the register) adds a ninth code, `unknown_reference`, through Appendix E.8: to P2.1's `reason_code_valid` CHECK, to P3.1's `REASON_CODES` and as one `test_rejections` case. The practice data needs none.

**`src/gisdb/ingest.py`: `run_ingest(paths: list[Path], session_factory=SessionLocal) -> dict`** (P3.2):
1. **Transaction 1:** insert `IngestRun(status="running", files=[])` and commit. Log `ingest.run.started`.
2. **Transaction 2 (the whole run's data).**
   - Preload `{trajectory_id: (id, content_hash)}` and `{zone_id: (id, content_hash)}`. Keep `seen_in_run = {(entity, key): content_hash}`.
   - For each file:
     - Read the bytes; record `{path, sha256, records}` in `files`; log `ingest.file.read`.
     - For each record, `seen += 1`, then:
       - **Rejected** (`RecordRejected`): add an `IngestRejection` row (entity, source_file as given, record_index 0-based, record_key, reason_code, detail ≤ 500 chars, payload = the raw record), `rejected += 1`, log `ingest.record.rejected`.
       - **Key already in `seen_in_run`:** the same hash gives `duplicates += 1` (log `ingest.record.duplicate`); a different hash is rejected `duplicate_key_conflict`. Otherwise set `seen_in_run[key] = hash` and continue with the DB comparison.
       - **Key not in the DB:** insert, `inserted += 1`. For trajectories, `session.add(...)`, then `session.flush()` for the id, then `session.execute(insert(TrajectoryPoint), rows)`.
       - **Hash differs from the DB:** update the scalar columns, `content_hash`, `source_file`, `last_ingest_run_pk` and `updated_at = datetime.now(UTC)`, then replace the points (below). `updated += 1`.
       - **Same hash:** write nothing, `unchanged += 1`.
   - Finally set the counts, `files`, `status="succeeded"` and `finished_at`, commit, and log `ingest.run.finished` (counts, `duration_ms`).
3. **On any exception:**
   - roll back;
   - in a new transaction set `status="failed"`, `error=str(exc)[:500]` and `finished_at`, then commit;
   - log `ingest.run.failed` and re-raise; the CLI exits 1.

**Point replacement rule.** Never reassign `trajectory.points`. Always use Core statements: `session.execute(delete(TrajectoryPoint).where(TrajectoryPoint.trajectory_pk == pk))`, then `session.flush()`, then `session.execute(insert(TrajectoryPoint), rows)`. Otherwise the unit of work can write new rows before deleting old ones, which collides on `UNIQUE (trajectory_pk, ts)`.

**Idempotency guarantee.** Re-running with unchanged inputs writes no trajectory, point or zone row. It reports `inserted = 0` and `updated = 0`, with `unchanged` equal to the number of distinct valid records. Only a new `ingest_runs` row and its rejection rows are added.

**Contract first.** P4.1/P4.2 ship every field above, with `analysis = None` and empty lists. P6.5 only fills them, so the client contract never changes. `null` means "not analyzed", which is distinct from zero counts.

**Filling the analysis fields (P6.5):**
- **Trajectory `analysis`:** comes from `trajectory_metrics` joined to `analysis_runs`. `analyzed_at` is the run's `finished_at`; `stale` is `metrics.input_hash != trajectories.content_hash`. It is `null` when there is no metrics row.
- **Zone `analysis`:** `pass_count` = count of its `zone_passes`; `trajectory_count` = count of distinct `trajectory_pk`. It is `null` when no succeeded `analysis_runs` row exists.
- **Lists:**
  - a trajectory's `zone_passes` are ordered by (`entry_time`, `zone_id`), i.e. chronologically along the track, which suits a web client's timeline;
  - a zone's `passes` by (`trajectory_id`, `seq`);
  - `intersections` by (`other_trajectory_id`, `seq`).
- **Intersection perspective:** a row where the viewed trajectory is `b` is flipped. `other` becomes `a`; `time_self`/`alt_self_m` take the b-values; `kind` stays as stored. Overlap start and end follow the direction of trajectory A, the one with the lower `pk` (the first ingested; FLT-1001 in X1).
- **Queries:** lists load the analysis for the whole page in one extra query, so there is no N+1.

**Errors and headers:**
- 422 is FastAPI's default validation body `{"detail": [...]}`.
- Unhandled exceptions give 500 `{"detail": "internal server error", "request_id": "<id>"}` with no traceback in the body (§6.f).
- Every response, including 404, 422 and 500, carries `X-Request-ID`. The inbound value is kept if it matches `^[A-Za-z0-9._-]{1,64}$`; otherwise it is replaced by `uuid4().hex`.
- Datetimes serialize as ISO-8601 UTC with `Z`. Internal `id`/`*_pk` values never appear.

### 6.g Geospatial analysis

**Definitions** (they match the brief text in §8.3):
- **Earth model:** a sphere with R = 6371.0088 km. `NM_TO_KM = 1.852` and `FT_TO_M = 0.3048`, both exact.
- **Path:** between consecutive time-ordered positions, a trajectory follows the minor great-circle arc at constant speed. Position on an arc is slerp; never interpolate raw lat/lon.
- **Time and altitude at a point inside segment i** are linear in the arc-length fraction f: `t = t_i + f·(t_{i+1} − t_i)` and `h = h_i + f·(h_{i+1} − h_i)`. If either altitude is null, `h` is null.
- **Length:** `length_km` is the sum of segment arc lengths. `length_3d_km` is `Σ hypot(θ·(R + h̄), Δh)`, which is null if any altitude is null; never the straight ECEF chord. `duration_s = ended_at − started_at`.
- **Zone:** a closed disc of great-circle radius `radius_km` around the centre.
- **Pass:** a maximal part of the path inside the disc. Its entry/exit kinds:
  - `track_start` / `track_end` when the track starts or ends inside;
  - `touch` when the path only reaches the boundary (miss distance within ±`TOL_KM`), or the pass is ≤ `TOL_KM` long;
  - otherwise `crossing`.

  A vertex on the boundary never splits or duplicates a pass. `distance_inside_km` and `duration_s` (exit − entry) come with each pass.
- **Intersection of two trajectories:**
  - every point where their paths meet: kind `crossing`. Shared vertices and shared endpoints count, each found once.
  - stretches along the same great circle (within `TOL_KM`) are reported as an `overlap_start` / `overlap_end` pair along trajectory A, with no crossings inside them.
  - each row carries both trajectories' interpolated times and altitudes, and `time_gap_s = |time_a − time_b|`.
- **Tolerance:** `TOL_KM = max(0.001, coordinate quantization)`. Practice data has 6 decimals, which is 0.11 m, so `TOL_KM = 0.001`. Also `TOL_RAD = TOL_KM / R` and `ZERO_RAD = 1e-12`.
- **Provenance:** `algorithm_version = "sphere-nvector-v1"`, `earth_radius_km = 6371.0088`, `tol_km = 0.001`, stored on `analysis_runs`.

**P6.1 specification: `src/gisdb/geodesy.py`.** This block is verbatim from geo.md P6a (verified: implemented as written, it passes). The P6.1 prompt carries it unchanged, with `<EARTH_RADIUS_KM=6371.0088>` and `<TOL_KM=0.001>` in the constants line.

```text
Model and conventions
- Sphere: EARTH_RADIUS_KM = 6371.0088. TOL_KM = 0.001 (1 m) for every boundary, tangency, overlap and dedupe decision; TOL_RAD = TOL_KM / EARTH_RADIUS_KM; ZERO_RAD = 1e-12 (shorter segments are "stationary").
- Internally every position is an n-vector (unit 3-vector). NEVER interpolate, average or subtract raw lat/lon. Convert to lat/lon only for output.
- Fractions f along a segment are fractions of ARC LENGTH; time and altitude at f are linear: t = t0 + f*(t1 - t0).
- Segments are minor arcs (< 180 deg). Circles need 0 < radius_km < 10000.

Types: @dataclass(frozen=True) TrackPoint(lat, lon, time: datetime | None = None, alt_m: float | None = None);
ZonePass(seq, entry_kind, exit_kind, entry_lat, entry_lon, entry_time, entry_alt_m, exit_lat, exit_lon, exit_time, exit_alt_m, distance_inside_km, duration_s | None);
TrackHit(kind, lat, lon, seg_a, seg_b, dist_along_a_km, dist_along_b_km, time_a, time_b, alt_a_m, alt_b_m).

1 to_nvec(lat, lon) = (cos(phi)cos(lam), cos(phi)sin(lam), sin(phi)); from_nvec(v) = (deg(atan2(z, hypot(x, y))), normalize_lon(deg(atan2(y, x)))); normalize_lon(x) = ((x + 180) % 360) - 180.
2 angle(a, b) = atan2(|a x b|, a . b)   [radians, accurate from 0 to pi; never acos(a . b)]
3 distance_km(lat1, lon1, lat2, lon2) = R * angle(...). haversine_km(...): h = sin^2(dphi/2) + cos(phi1)cos(phi2)sin^2(dlam/2); clamp h to [0, 1]; return 2R*atan2(sqrt(h), sqrt(1-h)). (An independent formula, used to cross-check.)
4 path_length_km(points) = sum of consecutive distance_km (0 for < 2 points). path_length_3d_km(points) = sum of hypot(theta*(R + (h1+h2)/2000), (h2-h1)/1000) with h in metres; None if any alt_m is None. (Not the straight ECEF chord: it tunnels through the Earth.)
5 interpolate(a, b, f): theta = angle(a, b); if theta < ZERO_RAD return a; n = unit(a x b); u = n x a; return a*cos(f*theta) + u*sin(f*theta).
6 segment_circle_interval(a, b, c, radius_km) -> (f0, f1, is_touch) | None   [the part of arc a->b inside the closed disc]
   rho = radius_km/R; theta = angle(a, b)
   if theta < ZERO_RAD: return (0.0, 1.0, False) if angle(a, c) <= rho else None
   n = unit(a x b); u = n x a; A = a.c; B = u.c; C = n.c
   xt  = atan2(|C|, hypot(A, B))   # angular distance from c to the great circle
   tau = atan2(B, A)               # angle from a (towards b) of the point nearest c
   if xt > rho + TOL_RAD: return None
   if xt >= rho - TOL_RAD:         # tangent band
       t = tau mod 2pi; return (t/theta, t/theta, True) if t <= theta else None
   delta = acos(min(1, cos(rho)/cos(xt)))      # spherical Pythagoras: cos rho = cos xt * cos delta
   for s in (0, 2pi, -2pi): t0 = max(0, tau-delta+s); t1 = min(theta, tau+delta+s); if t0 <= t1: return (t0/theta, t1/theta, False)
   return None
7 circle_passes(points, center_lat, center_lon, radius_km) -> list[ZonePass]
   - 0 points: []. 1 point: inside -> one pass track_start -> track_end (0 km, 0 s), else [].
   - Walk the segments in order, calling 6. Extend the open pass with segment i's interval iff the open pass ended on segment i-1 with (1-f1)*len(i-1) <= TOL_KM AND f0*len(i) <= TOL_KM; otherwise start a new pass. (A vertex on the boundary never splits or duplicates a pass; a stationary segment inside extends the duration.)
   - entry_kind = "track_start" if the pass starts on segment 0 with f0*len0 <= TOL_KM; else "touch" if every piece was a touch or the pass length <= TOL_KM; else "crossing". exit_kind is symmetric, with "track_end" on the last segment.
   - entry/exit lat/lon via interpolate; time/alt by linear f; distance_inside_km from cumulative lengths; duration_s = exit_time - entry_time; seq = 1, 2, ... in track order.
8 segment_intersections(a1, b1, a2, b2) -> list[(kind, nvec)]
   if angle(a1, b1) < ZERO_RAD or angle(a2, b2) < ZERO_RAD: return []
   n1 = unit(a1 x b1); n2 = unit(a2 x b2); theta1 = angle(a1, b1)
   if |n1.a2| <= TOL_RAD and |n1.b2| <= TOL_RAD:      # co-linear: arc 2 lies on great circle 1 within 1 m
       u1 = n1 x a1; t(p) = atan2(p.u1, p.a1); lo, hi = sorted(t(a2), t(b2)); if hi - lo > pi: lo, hi = hi, lo + 2pi
       t0 = max(0, lo); t1 = min(theta1, hi)
       if t1 - t0 < -TOL_RAD: return []
       if t1 - t0 <= TOL_RAD: return [("crossing", interpolate(a1, b1, t0/theta1))]
       return [("overlap_start", interpolate(a1, b1, t0/theta1)), ("overlap_end", interpolate(a1, b1, t1/theta1))]
   x = unit(n1 x n2)
   for p in (x, -x): if on_arc(p, a1, b1) and on_arc(p, a2, b2): return [("crossing", p)]
   return []
   on_arc(p, a, b) := angle(a, p) + angle(p, b) - angle(a, b) <= TOL_RAD   (p is already on both great circles)
9 bounding_cap(points) -> (centre_nvec | None, radius_rad): centre = unit(sum of n-vectors), radius = max_i(angle(centre, mid_i) + theta_i/2), mid_i = interpolate(seg_i, 0.5) (a single point: radius 0); if |sum| < 1e-9 return (None, pi). Every point of the track lies inside this cap.
   track_intersections(a_points, b_points) -> list[TrackHit]
   - Skip the pair if the two bounding caps are disjoint (angle(centres) > rA + rB + TOL_RAD). Skip segment pairs with angle(mid_i, mid_j) > (theta_i + theta_j)/2 + TOL_RAD, and zero-length segments. (Caps, not lat/lon boxes: boxes break at +-180, at the poles and on poleward-bulging arcs.)
   - For each hit: f = min(1, angle(seg_start, p)/theta) on each track; times and alts by linear f; along-track km from cumulative lengths.
   - Merge overlap pieces contiguous along track A (gap <= TOL_KM); drop crossings inside a merged overlap (+-TOL_KM); dedupe crossings with |d dist_along_a| <= TOL_KM and |d dist_along_b| <= TOL_KM (a shared vertex is found by up to 4 segment pairs). Return sorted by dist_along_a_km.
```

- Reads through `gisdb.db.SessionLocal` and `gisdb.models`.

- Prints one line per failed check, then `INVARIANTS OK (<n> checks)` and exit 0, or `INVARIANTS FAILED (<k> of <n>)` and exit 1.

Checks:
1. Every `crossing` or `touch` endpoint of a pass lies at `radius_km ± 0.001` km from its zone centre.
2. Every `track_start` / `track_end` endpoint equals the trajectory's first/last point within 0.001 km and lies inside the zone (≤ `radius_km` + 0.001).
3. Per pass: `entry_time ≤ exit_time`, both within [`started_at`, `ended_at`], and `distance_inside_km ≥ 0`.
4. Every intersection point lies on segment `segment_a` of A and segment `segment_b` of B: `distance(p_i, x) + distance(x, p_{i+1}) − distance(p_i, p_{i+1}) ≤ 0.001` km.
5. `time_gap_s == |time_a − time_b|` within 0.001 s.
6. `length_km` equals the sum of `Geodesic(6371008.8, 0.0).Inverse(...)["s12"]/1000` over consecutive stored points within 1e-6 km.
7. `trajectory_metrics` count equals `trajectories` count; the latest `analysis_runs` row has status `succeeded`; no metrics row is stale (`input_hash == content_hash`).

### 7.2 Exact JSON shapes


| Field | Type | Unit / format |
|---|---|---|

| `callsign` | string or absent | |

| `origin`, `destination` | 4-letter airport code strings | |
| `positions[].ts` | string or integer | ISO-8601 with `Z` or `±HH:MM`, or integer Unix epoch seconds |

- `id` is the natural key.

### 7.7 Answer key and generator method

**Command:** `uv run --no-project --with geographiclib python practice/generate_sample_data.py`, run from the repo root.
- It is stdlib-only apart from geographiclib, which serves for construction (`Direct`/`Inverse`) and as the length oracle.
- It must **never** import `gisdb`, and never call closed-form circle or arc intersection code.
- `practice/` is outside the service's lint scope (§6.a `extend-exclude`), so the generator may print its report freely. The same holds for Step C's `check_answer_key.py`.

**Brute-force method:**
- **Parsing.** Normalize like §6.d (sort, dedupe, UTC, units), with independent code.
- **Lengths.** Σ `Geodesic(6371008.8, 0.0).Inverse(...)["s12"]/1000`, cross-checked against an n-vector sum within 1e-6 km. Store 6 decimals.
- **Zone boundaries.**
  - Sample each segment by slerp at n = max(2, ⌈len/0.5 km⌉ + 1) fractions.
  - Compute g = R·angle(p, c) − r. Bisect every sign change (60 steps).
  - Refine every local minimum of the sampled g by golden-section search (80 steps).
    - If |g_min| ≤ 0.001 km, it is a touch: one pass with entry = exit at the minimum, both kinds `touch`.
    - **The touch rule takes precedence.** Discard any roots bracketed around that minimum. S7 dips about 1 mm inside (sampled minimum −0.0013 m), and 0.5 km sampling brackets two sign changes about 19 m apart that would otherwise make a crossing pass.
    - If g_min < −0.001 km and the minimum's sample and both neighbours are outside (a dip narrower than the sampling step), bisect the two roots on either side of the minimum. A safety net: it fires nowhere in the practice data (S9's 0.864 km chord holds two samples, 3.351 m inside, so ordinary sign changes bracket it; verified by instrumenting the generator).
  - Merge inside intervals that meet at a vertex (gap ≤ 1 m). Label kinds as in §6.g.
  - Times and altitudes are linear in the segment fraction.
- **Crossings ("sampling + local refinement").**
  - Scan each pair with A = the lexicographically smaller `trajectory_id` (= the first ingested, so A matches the build's lower `pk`).
  - **Vertices first.** Test every vertex of each track against every arc of the other track. A vertex within 1 m of the arc's great circle that lies on the arc within 1 m is a crossing. This finds shared vertices and endpoints (X2, X6) whatever their floating-point signs.
  - For each segment pair whose midpoints are within (len_a + len_b)/2 + 1 km, sample B every ≤ 0.5 km and compute the signed distance to A's great circle, R·asin(n_A·p).
    - Bisect sign changes (60 steps), using the inclusive test g[k]·g[k+1] ≤ 0 and treating a sample with |g| ≤ 1e-9 km as a root.
    - Keep a root if it lies on arc A within 1 m.
    - Verified: a literal strict test (`< 0`) finds X6 with FLT-1003 as A but not with FLT-1007 as A.
  - If |signed distance| ≤ 1 m along the whole of a segment piece, it is co-linear: project B's ends onto A for the overlap interval, merge contiguous overlap intervals along A, and drop crossings inside them (vertex hits included).
  - Deduplicate hits within 1 m on both tracks.
- **Completeness.** Scan all 100 trajectory × zone pairs and all 45 trajectory pairs. The key lists everything found.

**Self-check report** (stdout), one line per scenario:
- format: `S7 PASS touch at (54.003101,-16.581974) 11:37:30Z`;
- 25 lines (D1–D7, S1–S10, X1–X8);
- then `FOUND SET == EXPECTED SET` for passes and intersections (the line also compares the per-trajectory, per-zone and after-analysis counts);
- last line `SELF-CHECK OK (25 scenarios)`, exit 0; any FAIL exits 1.

### 8.3 Analysis definitions (exact text for the brief)

```text
Analysis definitions
- Treat the Earth as a sphere with radius R = 6371.0088 km. Unit conversions are exact: 1 NM = 1.852 km, 1 ft = 0.3048 m.
- Between two consecutive position reports of a flight (ordered by time), the aircraft flies along the shorter great-circle arc between them at constant speed. A flight's path is the sequence of these arcs.
- Flight length: the sum of the great-circle distances between consecutive positions, in km. (Bonus: a length that also accounts for altitude changes.)
- A zone is the set of points within its radius of its centre, measured as great-circle distance, boundary included.
- Zone entries and exits: for every flight and every zone, report each pass of the flight's path through the zone with its entry point and exit point (latitude, longitude) and the time the flight is at each point. If a flight starts inside a zone, that pass's entry is the flight's first position; if it ends inside, the exit is its last position. If the path only touches the boundary (it comes within 1 m of the boundary but never more than 1 m inside), report it as one pass whose entry and exit are the same point, marked as a touch.
- Track crossings: for every pair of flights, report each point where their paths intersect, with the time each flight is at that point. A position shared by both paths (for example a common waypoint, start or end) counts as an intersection. If two paths run along the same great circle for a stretch, report where the shared stretch starts and ends instead of individual crossing points.
- Times at points between two reports follow from constant speed: proportional to the distance travelled along the arc. Points less than 1 m apart are the same point.
```
